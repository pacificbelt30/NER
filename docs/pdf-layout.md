# PDF処理とエラー方針

[ドキュメントの目次](README.md) · [性能・レイアウト評価](benchmarks.md)

## 処理の流れ

1. PDFからページ・ブロック・行・文字の位置と、フォント・色・方向を抽出します。
2. 表のセルを分離し、翻訳対象の英文と、そのまま残す文字列を判定します。
3. URL・コードなどを保護し、ブロック内を分割して翻訳します。
4. 保護文字列が壊れていないか検証し、元の文字列を復元します。
5. 訳文が収まる領域を決めてから、対象の原文だけを除去・配置します。
6. 失敗した箇所を保持し、必要に応じてレポートを付けて一時ファイルへ保存します。保存成功後に出力先を置き換えます。

本番のPDF操作にはPyMuPDFを使います。別ライブラリへの切り替えや、背景を白く塗って訳文を重ねるだけの処理にはしていません。元の入力PDFは変更しません。

## 翻訳対象の判定

文字数だけで翻訳の有無を決めず、英単語の構造と保護対象を使って保守的に判定します。

| 内容の例 | 自動翻訳の扱い |
| --- | --- |
| `Getting started`、`Go now.` | 短い文句でも対象 |
| `Read https://example.org/` | 指示文は翻訳し、URLは保護 |
| `Installation`、`Ready` | 単語だけならそのまま保持 |
| 数字、略語だけのラベル、単独URL | そのまま保持 |
| コード構文を持つブロック | 元の位置・文字で保持 |
| 主に非ラテン文字の文章 | 自動翻訳の対象外 |

翻訳を省略した見出しも、後続ブロックの文脈として使います。単語を直接 `TranslationService` に渡す明示的な翻訳まで禁止する機能ではありません。

判定は英日PDF向けのヒューリスティックです。一般的な言語判定器や固有表現認識器ではありません。`PaperExtract.selection_decisions` で判定理由を確認できます。

選択可能な文字はあるものの対象の英文がないPDFは、モデルへ問い合わせずに保存できます。空白・画像のみのPDFは、既定の方針では原文にOCR等の説明を付けて返します。

## ブロック翻訳と文字列の保護

ブロックには安定したID、見出し・段落・リストなどの役割、近くの見出し文脈、行・spanの位置と書式、保護範囲を持たせます。番号付き・箇条書きの行は別の単位として扱います。

インラインコード、URL、外部リンクのラベル、メール、IP、パス、コマンドオプションなどを保護トークンに置き換えてモデルへ渡します。文中の `www.` や一般的な裸のドメインも保護対象です。外部リンクのラベルは、現在の実装では原文を保持します。

モデル入力には `Xn` 形式のIDを使います。欠落・重複・書き換え・余分なIDがある訳文は採用しません。日本語の語順に合わせてトークンが移動することは許可します。検証後に保護した元の文字列を正確に復元します。

分割は文、節、単語、書記素クラスタの境界を優先し、保護トークンの途中では切りません。Bergamotは既定700文字、他の方式は2000文字を分割目安とし、チャンクを元のブロックへ再結合します。途中結果や不正な結果はキャッシュしません。

この方針は隣接するOtranslatorの実装を読み取り専用で調査し、Pythonで独立して実装したものです。Otranslatorをインポート・実行せず、そちらのファイルも変更していません。ブロックの扱いを参考にしたこと自体は、翻訳品質の向上を意味しません。

## URL・コードの配置

独立したコードブロックや翻訳しない単独URLは元の位置に残します。段落内のコード・URLは訳文と一緒に流し込み、日本語の語順や折り返しに合わせて位置が変わる場合があります。

訳文はエスケープしたHTMLで配置します。URL・リンクラベルのクリック領域も新しい位置に合わせます。日本語リンクで複数の小さい領域が生成される場合は、同じ行の隣接領域を正規化します。文字列が残っていることと、クリック領域が正しいことは別々に検証します。

## 配置の優先順位

段落・見出し・表・保護文字列を含むブロックは、共通のHTML配置経路を使います。

1. 元の矩形と元の文字サイズで、通常の折り返しを試します。
2. 周囲に確認できた空きがある場合、元の文字サイズのまま領域を広げます。
3. それでも収まらなければ、最小**1pt**まで縮小します。
4. 安全に配置できなければ原文を保持し、有効な訳文の全文を末尾のレポートへ載せます。

原文より大きい文字サイズにはしません。ただし原文が1pt未満なら1ptを開始値とします。1ptは配置の下限であり、読みやすさを保証するサイズではありません。ブロックを手動調整するUIは未実装です。

`PageLayoutSpace` が元の文字、画像、ベクタ図形、表領域、先に配置した訳文を障害物として扱います。拡張は文字の進行方向と折り返し方向にそれぞれ最大36ptです。段組みの境界、クロップ範囲、色付きパネルなどを越えないよう制限します。幅と高さを同時に変える場合も、斜め方向の障害物との重なりを確認します。

中央見出しは左右対称に広げ、表のセルや不確かな固定ラベルは広げません。元から重なりがある不確かな配置も、拡張を抑制します。小さい縦余白を設け、日本語のグリフが判定済みの矩形からはみ出さないようにします。

元のブロックの色、先頭spanの強調情報、検出した横方向の揃え、0 / 90 / 180 / 270度の文字方向を配置に使います。モデル由来の単独改行は折り返しとして空白へ変え、明示的な段落区切りや保護文字列内の改行は残します。

## 表の処理

罫線のある表はPyMuPDFの `find_tables(strategy='lines_strict')` でセルを検出してから段落をまとめます。文字の中心点で各セルへ一度だけ割り当て、結合セルにも対応します。

セル内の文章だけを翻訳し、単語・数字・単独URL・コードは元のフォントと位置に残します。訳文はセル枠内に固定し、隣のセルへ拡張しません。対象の文字範囲を透明に除去し、背景や罫線を保持します。ページの回転属性は文字の座標系に合わせて扱います。

罫線がない表は、コンパクトな行が3行以上続き、同じ列の開始位置と規則的な行間が繰り返される場合に保守的に推定します。不明瞭な同一行のラベルは、横につなげず独立した有界の単位にします。

不規則な間隔、罫線のない結合セル・複数行セル、斜めの文字、スキャン表は改善の余地があります。すべての表を正確に復元する実装ではありません。[表の測定結果](benchmarks.md#表の評価)も参照してください。

## エラー時の出力

`ERROR_POLICY: preserve` が既定です。成功した箇所は翻訳し、失敗した箇所は原文を残します。ブロックの失敗箇所には赤枠・注釈を付け、末尾の日本語レポートで原文のページ、ブロック、説明を確認できるようにします。文書全体の注意など、箇所を特定できない場合もレポートに記録します。

| 失敗 | 出力の扱い |
| --- | --- |
| 翻訳リクエストの失敗、保護トークンの不正 | 原文ブロックを保持し、注釈・レポートに記録。不正・不完全な訳文は使わない |
| 有効な訳文が1pt以上で配置できない、未対応の斜め文字など | 原文を保持し、有効な訳文の全文を改ページしながらレポートへ掲載 |
| ページの準備・書き換えに失敗 | そのページ全体を原文のまま残し、他のページの成功した処理を再適用。配置できなかった訳文も掲載 |
| CLI・ライブラリでエンジンを準備できない | 原文と説明のPDFを作成。オンライン方式へ切り替えない |
| 本文抽出の失敗、空白・画像のみのPDF | 原文に抽出失敗・OCR等の説明を追加 |
| 指定フォントが使用できない | 標準の日本語フォントへ切り替え、注意を記録 |
| ジョブの比較PDF作成だけ失敗 | 翻訳PDFを取得可能にし、API/UIに注意を表示。保存後の失敗のためPDF内レポートには追加しない |
| 入力が読めない・暗号化されている・ページがない、保存できない、中止 | 明示的な失敗・中止。PDFの出力は保証できない |

ページの書き換え途中で失敗した場合は、変更していない入力PDFから出力用文書を作り直します。ユーザーが入力PDFに付けていた未適用の削除注釈を、翻訳時に一緒に適用することも防ぎます。

翻訳PDFには構造化した `ner-translation-report.json` も添付します。同名の添付があれば連番にし、既存の添付を上書きしません。含めるのは原文の抜粋、エラー位置、有効な未配置訳文などです。内部例外、認証情報、不正なモデル応答は含めません。

比較用PDFは原文ページと対応する出力ページを交互に並べ、追加レポートは最後にまとめます。元のページとレポートのページを取り違えて交互配置しない構成です。

### CLI・APIからの確認

CLIは注意付きPDFでも保存できれば終了コード0とし、標準エラーに件数を出します。入力・保存などの致命的な失敗は非0です。

APIは注意付きでもPDFが保存できた場合 `status: succeeded` とします。`result_summary.outcome` と `warnings` で完全完了・一部完了・未翻訳・注意付き完了を区別してください。詳細は[API仕様](api.md)に記載しています。

### 厳格に停止するモード

```yaml
ERROR_POLICY: strict
```

または `TextraConnection(..., error_policy='strict')` を指定すると、翻訳・配置エラーでは新しいPDFを書き出さず、例外として扱います。既定の原文保持モードとの切り替えです。

## 現在の制約

複数段組みの読み順、文中の混在した強調・フォント、任意の傾き、複雑な罫線なし表、数学記号、内部リンク先などは、文書ごとに追加の検証が必要です。文字を抽出できること、訳文を枠に入れられること、意味が正しく訳されることは、それぞれ別の評価です。

小さな検証用文書での結果から、任意のPDFに対する維持率や翻訳品質を保証していません。測定条件と残る改善点は[性能・レイアウト評価](benchmarks.md)を参照してください。
