# 注意箇所の確認と手修正

[ドキュメントの目次](README.md) · [サーバとWeb UI](server.md) · [API仕様](api.md)

翻訳結果の「注意箇所の確認・修正」で、原文と翻訳候補を見比べて採用方針を選べます。履歴から開いた結果も編集できます。

## 操作

1. 注意のある翻訳結果を開きます。「このページを表示」で原文・訳文の該当ページを表示できます。
2. 原文、候補、必要なら「原文のURL・コード・リンク先を確認」を読み比べます。
3. ブロックごとに採用方針を選びます。

| 方針 | PDFへの反映 |
| --- | --- |
| 未確認 | 自動処理の結果を維持し、注意を残す |
| 原文を採用 | その箇所の原文を保持し、人が確認したものとして注意を解消する |
| 翻訳候補を採用 | 表示した候補を、人の判断で本文へ配置する |
| 手入力で修正 | 入力した本文を配置する。URLも本文中で修正できる |

4. 「下書きを保存」で、選択と修正文をサーバに保存します。履歴から開き直したりサーバを再起動したりしても編集を再開できます。
5. 「確認内容をPDFに反映」で修正版を生成します。未保存の入力も先に保存します。元の履歴・PDFは残り、修正版は新しい履歴になります。訳文PDFと比較用PDFを取得できます。

保存前に別のPDFへ移動したりページを閉じたりする場合は、未保存の変更があることを確認します。通信エラー時は画面内の入力を残します。別の画面で先に保存された場合は、上書きを防ぐためエラーを表示します。必要な入力を手元にコピーしたうえで「下書きを読み直す」を使ってください。

## 候補とURL

URL・コードの検証を通らなかった候補も、確認画面で参照できます。**自動では採用しません。** 元のURLが欠けていたり変更されていたりする可能性があるため、原文と比較してください。途中までしか取得できなかった候補や内部の保護記号が残る候補は、そのまま採用できません。手入力で全文を補ってください。

本文に入力したURLを変更すると、PDF上のクリック先もそのURLに合わせます。原文から変わっていないリンクラベルは元のクリック先を保持します。ラベルだけのリンク先を変更したい場合は、本文に正しいURLを直接入力してください。コードやURLはHTMLとして実行せず、文字として配置します。

修正文は1ブロック2万文字以内です。URL内の `fi`・`fl`・`ff` が合字に置き換わってコピー文字列が変わる問題を避けるため、該当URLは等幅フォントで描画します。

## 反映できない修正

配置は通常の翻訳と同じ枠・障害物・表のセル・最低1ptの制約で再計算します。修正文が収まらなかったり、斜めの本文など配置未対応の箇所だったりする場合は、原文を保持して注意と全文をPDF末尾に残します。画面でも「この修正は安全に配置できず」と表示し、反映済みとして扱いません。文章を短くして再編集するか、「原文を採用」で確認を完了できます。

OCR不足、ページ全体の描画失敗、エンジン設定など、ブロック編集では解消できない注意は説明のみ表示します。

## 以前の履歴

この機能の追加前に作成した履歴には、再配置に必要なデータがありません。「原本を再翻訳して編集を始める」で新しい履歴と編集用データを作成してください。この操作には翻訳エンジンが必要です。再翻訳には元の履歴の翻訳方式を使い、元の履歴は変更しません。

編集用データがある履歴では、確認内容の反映時に翻訳モデル・外部APIを呼びません。保存した元の抽出情報と全ブロックの訳文を使い、原本からページ全体を再配置します。以前の訳文を画像で塗りつぶして重ねる方式ではないため、隣接ブロックや表の配置制約も再確認します。

## 保存と追跡

各履歴の保存先に `review-manifest.json` と、保存時に `review-draft.json` を保持します。候補、原文、座標、翻訳結果、採用方針を含むため、PDFと同じ保存期間・アクセス制限の対象です。設定ファイルやAPI認証情報は含めません。未承認の候補は自動生成PDFに埋め込みません。

修正版PDFには `ner-human-review.json` を添付し、人が選んだ方針・修正文・反映成否を記録します。通常のPDFビューアで本文を読めますが、添付ファイルを読むツールでも判断内容を確認できます。
