# サーバとWeb UI

[ドキュメントの目次](README.md) · [API仕様](api.md)

## 起動とログイン

[翻訳設定](configuration.md)を用意したら、リポジトリのルートで実行します。

```sh
pipenv run python -m ner.auth setup
pipenv run python api_server.py
```

ブラウザで <http://127.0.0.1:8000/> を開き、対話コマンドで作成したユーザー名とパスワードでログインします。アカウント作成は初回のみです。既定のパスワードはありません。未設定の場合はログイン画面に初回設定の手順が表示され、非公開APIは `AUTH_NOT_CONFIGURED` を返します。

NERはサーバ全体で1アカウントを使います。公開のユーザー登録やユーザー別の履歴分離はありません。同じアカウントでログインしたクライアント間で、履歴と設定を共有します。

## 画面の使い方

### 新しく翻訳

1. PDFを選択するか、ドロップします。1ファイル50 MiBまでです。
2. 翻訳方式と、比較用PDFも作るかを選択します。
3. 翻訳を開始します。アップロード、ページ・ブロック・チャンク単位の進捗を表示します。
4. 完了後に原文と訳文を読み比べ、必要なPDFを保存します。

原文と訳文は同じページ番号で表示し、ページ送りと拡大に対応します。プレビューはサーバが生成したPNGです。ブラウザ内蔵のPDFビューアを使わず、ダウンロードするPDFには選択可能な文字を残します。

一部の翻訳・配置に失敗した場合は「注意付きPDFを作成しました」と表示します。原文を保持した箇所、エラー一覧、配置できなかった有効な訳文は、PDFの注釈と末尾のレポートで確認できます。

待機中のジョブはすぐに停止でき、実行中のジョブはチャンク間などの中止確認箇所で停止します。失敗・停止したジョブは、アップロード済みPDFを使って再試行できます。別の翻訳方式へ変更することもできます。

### 翻訳履歴

履歴はサーバに保存します。ファイル名検索、状態の絞り込み、ページ分け、結果の再表示、原文・訳文・比較用PDFの取得ができます。失敗・停止したジョブも一覧に残ります。

ブラウザの保存情報がない端末でも、ログインすれば履歴を取得できます。サーバを再起動しても完了済みの履歴とPDFは残ります。新しい翻訳の画面を開いても、受付済みのジョブは中止しません。

ブラウザ側には直近の受付情報だけを保存し、ページの再読み込み時に復元します。一時的な接続切断では自動で再接続します。再起動で処理中のジョブが中断された場合は `SERVER_INTERRUPTED` として再試行できる状態にします。処理途中から自動で再開する機能ではありません。

### 設定

保存期間の既定は**無期限**です。日数を指定する場合は、完了後1〜3650日で設定できます。

- 設定はサーバ全体に適用し、再起動後も保持します。
- 変更後に完了するジョブに新しい期間を適用します。
- 保存済みPDFの期限は変更しません。以前の仕様で1時間の期限が付いているPDFも、その期限を維持します。
- 有限の期限を過ぎたジョブは、履歴とファイルを自動で削除します。すでに削除したPDFは復元できません。

この画面では翻訳APIのURL・認証情報を編集できません。[翻訳設定](configuration.md)の `config.yml` を編集してください。

## 認証の仕組みとアカウント変更

認証には[FastAPI-Login](https://github.com/maxrdu/fastapi_login)、パスワードのハッシュ化には[pwdlib / Argon2](https://frankie567.github.io/pwdlib/)を使います。パスワードは平文では保存しません。

ログインセッションは12時間有効で、サーバ再起動後も継続できます。ブラウザではHttpOnly・SameSite=StrictのCookieを使います。ログアウトするとCookieを削除し、サーバ側でもそのセッションを失効させます。APIクライアントはCookieまたはBearerトークンを使用できます。

パスワードを変更・再設定する場合は、同じ保存先で初回設定コマンドを実行し、サーバを再起動します。

```sh
pipenv run python -m ner.auth setup
```

新しい署名用シークレットを作るため、再起動後は以前のトークンを使えません。PDF履歴と翻訳設定は変更しません。ログイン試行は接続元アドレスごとに1分間5回までです。

## 保存先と環境変数

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `NER_CONFIG_PATH` | `config.yml` | サーバが読む翻訳設定 |
| `NER_STORAGE_PATH` | `pdfstore/` | アカウント、セッション、ジョブとPDFの保存先 |
| `NER_COOKIE_SECURE` | 未設定 | `1` でCookieにSecure属性を指定 |

HTTPSでアクセスした場合もSecure属性を付けます。リバースプロキシでHTTPSを終端する構成では、`NER_COOKIE_SECURE=1` を指定できます。

保存先を変える場合は、アカウント作成とサーバ起動で同じパスを使用します。

```sh
export NER_STORAGE_PATH=/path/to/ner-data
export NER_CONFIG_PATH=/path/to/config.yml
pipenv run python -m ner.auth setup
pipenv run python api_server.py
```

アカウント作成コマンドだけ保存先を指定する場合は、`--storage /path/to/ner-data` も使えます。

```text
pdfstore/
  auth.json                 アカウントのハッシュ・署名用シークレット
  sessions.sqlite3          有効なログインセッション
  jobs/
    settings.json           保存期間設定
    <job-id>/
      job.json              履歴・状態・出力概要・注意事項
      progress.json         処理の進捗
      input.pdf             原文
      input_new.pdf         翻訳PDF
      comparison.pdf        比較用PDF（指定時）
      preview-*.png         表示用キャッシュ
```

`auth.json` とセッションDBは所有者用のファイル権限で作成します。`pdfstore/` と認証情報・モデルはGit管理の対象外です。履歴を移行する場合は、サーバを停止して保存先をバックアップ・復元し、翻訳設定とモデルのパスも合わせてください。

## サーバの実行構成

`python api_server.py` は `0.0.0.0:8000` で起動し、開発用の自動再読み込みを有効にします。再読み込みを使わず、ローカルから接続する例です。

```sh
pipenv run uvicorn api_server:app --host 127.0.0.1 --port 8000 --workers 1
```

APIサーバは**1ワーカー**で実行してください。キューはサーバプロセス内にあり、複数のAPIワーカーへ分散する構成には対応していません。受付上限は待機・実行・停止処理中を合わせて16ジョブで、PDFは別の1ワーカープロセスが順番に処理します。PyMuPDFをPythonスレッドから同時実行しない構成です。

## よくある状態

| 状態 | 確認すること |
| --- | --- |
| ログイン画面に初回設定が表示される | 起動時と同じ保存先でアカウントを作り、サーバを再起動する |
| 翻訳方式が「準備が必要」になる | `config.yml`、モデル、実行ファイルのパスを確認する |
| 設定済みなのに翻訳が失敗する | 外部サービスの認証・稼働状態、ローカルモデルサーバの起動を確認する |
| プレビューを表示できない | PDFを別タブで開くか、ダウンロードする。表示失敗だけでは完成済みPDFを破棄しない |
| 元の枠に訳文が収まらない | [配置とエラー時の方針](pdf-layout.md)に従い、原文と末尾のレポートを確認する |
